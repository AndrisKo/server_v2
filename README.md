# 📸 PixelVault — Сервис хостинга и оптимизации изображений

**PixelVault** — легковесный и быстрый веб-сервис для загрузки, автоматической оптимизации, хранения и просмотра изображений. Построен на современном стеке **FastAPI + PostgreSQL + Nginx + Docker**, с адаптивным интерфейсом в тёмной палитре **Bootswatch Solar**.

---

## 🚀 Быстрый запуск

### 1. Подготовка окружения
Скопируйте пример конфигурации и при необходимости отредактируйте параметры (порты, пароли):
```bash
cp .env.example .env
```

### 2. Запуск через Docker Compose
Запустите все сервисы (приложение, базу данных PostgreSQL и веб-сервер Nginx):
```bash
docker compose up -d --build
```

### 3. Открытие в браузере
Перейдите по адресу:
- **Веб-интерфейс**: [http://localhost:8088](http://localhost:8088) (или порт, указанный в `.env` как `PORT`)

---

## 🛠 Стек технологий

- **Backend**: Python 3.12, FastAPI, Uvicorn, Pillow (PIL), psycopg 3
- **Database**: PostgreSQL 16
- **Reverse Proxy**: Nginx (кэширование статики, `sendfile`, сжатие и маршрутизация)
- **Frontend**: Чистый HTML5, Vanilla CSS, Bootswatch Solar (тёмная палитра), Vanilla JS (без тяжёлых библиотек)
- **Инфраструктура**: Docker, Docker Compose

---

## 📋 Основные возможности сервиса

1. **Мультизагрузка и Drag-and-Drop** (`/upload`):
   - Загрузка файлов через системное окно выбора или простым перетаскиванием (до 20 файлов за раз).
   - Проверка формата файлов: **JPG, PNG, GIF**.
   - Ограничение размера: до **5 МБ** на файл.
   - Проверка целостности файла через Pillow (защита от поддельных и повреждённых файлов).

2. **Мгновенное сохранение и отдача**:
   - Файлы сохраняются напрямую на диск без задержек на синхронное пережатие.
   - Минимальное время отклика сервера при загрузке.

4. **Галерея фото** (`/images`):
   - Плиточный адаптивный просмотр всех сохранённых фотографий с пагинацией по 12 штук.
   - Полноэкранный просмотр изображений (Lightbox) в один клик.
   - Копирование прямой ссылки на изображение в буфер обмена.

5. **Реестр файлов и управление** (`/images-list`):
   - Таблица всех загруженных файлов из базы данных с пагинацией по 10 записей.
   - Отображение метаданных: оригинальное имя, размер в КБ, формат, дата загрузки.
   - **Безопасное удаление**: пользователь может удалить только те изображения, которые загрузил сам (проверка авторства по IP-адресу).

6. **Быстрая отдача через Nginx**:
   - Nginx настроен с директивами `sendfile on`, `tcp_nopush on`, `open_file_cache`.
   - Кэширование изображений браузером на 30 дней с заголовком `Cache-Control: public, max-age=2592000, immutable`.

7. **Резервное копирование и восстановление**:
   - Скрипты на Python для создания и восстановления согласованных бэкапов (SQL-дамп базы данных + архив файлов картинок).

## 📖 Справочник доступных функций по модулям

### 1. Маршруты веб-приложения (`app.py`)

| Маршрут | Метод | Описание |
|---|:---:|---|
| `/` | `GET` | Главная страница сервиса |
| `/upload` | `GET` | Форма загрузки изображений и отображение результатов |
| `/upload` | `POST` | Обработка загрузки: валидация, сжатие Pillow, сохранение в БД и на диск |
| `/images` | `GET` | Галерея изображений с пагинацией (по 12 шт.) |
| `/images/{filename}` | `GET` | Прямая раздача файла изображения |
| `/images-list` | `GET` | Таблица-реестр всех файлов с пагинацией (по 10 шт.) |
| `/delete/{image_id}` | `POST` | Удаление изображения из БД и файла с диска (только автором) |
| `/about` | `GET` | Страница с информацией об авторе проекта |
| `app_exception_handler` | — | Перехватчик ошибок (404, 500) с выводом в шаблоне `error.html` |
| `get_page_data(page, per_page)` | — | Универсальная функция расчёта данных пагинации |
| `get_client_ip(request)` | — | Определение IP-адреса пользователя (с поддержкой заголовка `X-Real-IP`) |

---

### 2. Работа с базой данных (`utils/db.py`)

| Функция | Назначение |
|---|---|
| `get_db_connection()` | Создаёт и возвращает соединение с PostgreSQL через библиотеку `psycopg`. |
| `init_db()` | Создаёт таблицу `images` и индекс по дате, если они ещё не существуют при старте. |
| `save_image_metadata(conn, ...)` | Сохраняет метаданные о файле (имя, оригинальное имя, размер, тип, IP автора) и возвращает `id`. |
| `get_images_page(page, page_size)` | Выполняет SQL-запрос с `LIMIT / OFFSET` и `COUNT(*)`, возвращая список записей для текущей страницы и общее число файлов. |
| `delete_image_by_id(image_id, client_ip)` | Удаляет запись из базы данных по `id`, предварительно сверяя IP-адрес автора. Возвращает имя удалённого файла. |

---

### 3. Обработка файлов (`utils/file_utils.py`)

| Функция | Назначение |
|---|---|
| `is_allowed_file(filename)` | Проверяет, входит ли расширение файла в список разрешённых (`png`, `jpg`, `jpeg`, `gif`). |
| `get_content_type(filename)` | Возвращает правильный MIME-тип для передачи в HTTP-заголовке (`image/jpeg`, `image/png` и т.д.). |
| `validate_image(contents, filename)` | Проверяет файл на пустоту, лимит размера (5 МБ) и валидность структуры через Pillow. Генерирует уникальное имя через `uuid4`. |

---

### 4. Логирование (`utils/logger.py`)

| Функция | Назначение |
|---|---|
| `log_action(action, message)` | Форматирует и записывает событие (Успех/Ошибка/Бэкап) с временной меткой в поток консоли и файл `logs/app.log`. |

---

### 5. Резервное копирование и восстановление (`scripts/`)

#### Создание бэкапа:
```bash
python3 scripts/backup.py
```
- Делает SQL-дамп базы данных через `docker exec ... pg_dump`.
- Упаковывает каталог с загруженными изображениями в `.tar.gz`.
- Сохраняет файлы в папку `backups/` с меткой даты и времени: `backup_ГГГГ-ММ-ДД_ЧЧММСС.sql` и `images_ГГГГ-ММ-ДД_ЧЧММСС.tar.gz`.

#### Восстановление:
```bash
# Восстановить самый свежий бэкап:
python3 scripts/restore.py

# Или восстановить конкретный файл:
python3 scripts/restore.py backups/backup_2026-10-24_120000.sql
```
- Восстанавливает структуру и записи в PostgreSQL через `psql`.
- Распаковывает соответствующий архив изображений обратно в хранилище.

## 🔒 Безопасность

- **Изоляция файлов**: Пользовательские имена заменяются случайными UUID4-хэшами (защита от Path Traversal и перезаписи файлов).
- **Валидация Pillow**: Картинка открывается и проверяется (`Image.open().verify()`), что предотвращает загрузку вредоносных скриптов под видом картинок.
- **Ограничение прав на удаление**: Удалить фото может только пользователь с того же IP-адреса, с которого производилась загрузка.
- **Параметризованные SQL-запросы**: Защита от SQL-инъекций за счёт использования плейсхолдеров `%s` в библиотеке `psycopg`.
